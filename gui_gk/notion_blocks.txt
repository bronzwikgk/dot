Here is the complete list of core Notion block types with their use cases, key attributes, and child component support.

### 📝 Text & Structure Blocks

| Block Type | Use Case | Key Attributes / Parameters | Supports Children? |
| :--- | :--- | :--- | :--- |
| **Paragraph** | Default text for writing notes, paragraphs, and general content. | `rich_text` (array of rich text objects for formatted text and inline mentions) | **Yes**, can contain nested blocks for indentation. |
| **Heading 1 / 2 / 3** | Create section titles to structure a document hierarchically. | `rich_text` (heading text); `is_toggleable` (boolean) makes it a collapsible toggle heading. | If `is_toggleable` is **true**, it can contain children that expand/collapse. |
| **Quote** | Highlight a block of text, often used for pull quotes or references. | `rich_text` (quoted text); supports `color` property. | **Yes**. |
| **Callout** | Draw attention to information with a distinctive background and emoji/icon. | `rich_text` (text); `icon` (emoji or file); supports `color`. | **Yes**, content is nested inside the callout. |
| **Code** | Display code snippets with syntax highlighting. | `rich_text` (code content); `language` (programming language); `caption`. | No (the `rich_text` array holds the content). |
| **Equation** | Display a mathematical formula or expression using LaTeX/KaTeX syntax. | `expression` (string of LaTeX/KaTeX code). | No. |
| **Divider** | Insert a horizontal rule to visually separate content sections. | No specific attributes. | No. |
| **Table of Contents** | Auto-generate a navigation index of headings on the current page. | No specific attributes. | No. |

### 📋 List & Interactive Blocks

| Block Type | Use Case | Key Attributes / Parameters | Supports Children? |
| :--- | :--- | :--- | :--- |
| **Bulleted List** | Create unordered lists for items without a specific sequence. | `rich_text` (list item text). | **Yes**, nested items create indented sub-lists. |
| **Numbered List** | Create ordered lists for steps, sequences, or prioritized items. | `rich_text` (list item text). | **Yes**. |
| **To-Do** | Create interactive checkboxes for task management and tracking. | `rich_text` (task description); `checked` (boolean state). | **Yes**, nesting allows sub-tasks. |
| **Toggle** | Create collapsible content that reveals details when clicked. | `rich_text` (toggle title); support for `color`. | **Yes**, the hidden content is nested inside the toggle. |
| **Synced Block** | Create a reusable content block that updates everywhere when changed. | `synced_block` object; when referencing, `synced_from` object points to original. | **Yes**, children are nested inside the block. |

### 🧩 Media & Embedded Blocks

| Block Type | Use Case | Key Attributes / Parameters | Supports Children? |
| :--- | :--- | :--- | :--- |
| **Image** | Insert images from a file upload or external URL. | `file` (uploaded file) or `external` (URL); `caption`. | No (has a `caption` rich-text property instead). |
| **Video** | Embed video files or external video links. | `file` (uploaded file) or `external` (URL); `caption`. | No. |
| **Audio** | Embed audio files for playback. | `file` (uploaded file) or `external` (URL); `caption`. | No. |
| **File** | Attach a file for download, supporting any file type. | `file` (uploaded file) or `external` (URL); `caption`; `name` (display name). | No. |
| **Bookmark** | Create a rich link preview for an external URL. | `url` (the URL to bookmark). | No. |
| **Embed** | Embed content from an external service (e.g., Google Maps, Figma) by providing a URL. | `url` (the embed source URL). | No. |

### 🏗️ Structure & Layout Blocks

| Block Type | Use Case | Key Attributes / Parameters | Supports Children? |
| :--- | :--- | :--- | :--- |
| **Column List** | Create a multi-column layout container. | Contains only `column` children. | **Yes**, it can contain **2 to 5 `column` blocks**. |
| **Column** | Define a single column within a `column_list` to hold content. | No specific attributes. | **Yes**, it contains actual content blocks (paragraphs, images, etc.). |
| **Child Page** | Create a new page nested within the current page. | This is a full `page` object with its own `properties` and `content`. | Conceptually a page, but the child hierarchy is managed via the parent-child relationship in the API. |
| **Breadcrumb** | Display the page's location within the workspace hierarchy for navigation. | No specific attributes. | No. |

### 📊 Database Blocks

| Block Type | Use Case | Key Attributes / Parameters | Supports Children? |
| :--- | :--- | :--- | :--- |
| **Table** | Create a simple grid table (not a full database) with rows and columns. | `table_width` (number of columns); contains `table_row` children. | **Yes**, must contain `table_row` children. |
| **Table Row** | Define a single row within a `table` block. | `cells` (array of rich text objects for each cell). | No. |
| **Board** | Create a Kanban-style board view of a database. | This is a **database view** block. Its `type` will be `board` and references a source database. | No. |
| **Gallery** | Create a gallery view of a database, showing a grid of items. | This is a **database view** block. Its `type` will be `gallery` and references a source database. | No. |
| **List** | Create a list view of a database. | This is a **database view** block. Its `type` will be `list` and references a source database. | No. |
| **Calendar** | Create a calendar view of a database with dates. | This is a **database view** block. Its `type` will be `calendar` and references a source database. | No. |

### 🔧 Other Blocks

| Block Type | Use Case | Key Attributes / Parameters | Supports Children? |
| :--- | :--- | :--- | :--- |
| **Link to Page** | Create a link to an existing page within your workspace. | Contains a reference to the target page's ID. | No. |
| **Template Button** | **(Deprecated)** Used to insert a pre-defined set of blocks with one click. | Contained the template content. **Deprecated as of March 27, 2023**. | N/A (deprecated). |

> **A Note on Children:** The "Supports Children?" column means a block can have other blocks nested inside it. This is the key to Notion's hierarchical and flexible data model. Blocks like `paragraph`, `toggle`, and `bulleted_list` can contain children to create indentation, lists, and collapsible content.
